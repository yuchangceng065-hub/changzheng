# 长征征途 · 交互式长征地图叙事科普

> 选择一支从不同起点踏上长征之路的红军部队，跟随行军路线，亲历长征征途。

面向「红色之旅 追梦铸魂」赛道的 Web 端交互式长征地图叙事科普作品：以中国地图为舞台，按四路红军分别呈现长征行军路线、关键历史节点与史料注记。

---

## 一、作品概览

全站由**顶部导航**串起五个页面：

| 页面 | 内容 |
| --- | --- |
| **首页** | 作品标题、长征总述、关键数字、四个入口卡片 |
| **部队介绍** | 四路红军逐一说明：番号、出发地与终点、历时、行程、兵力、途经省份、概述、关键事件标签，并可直接进入该部队的地图 |
| **深度交互** | 主交互界面：选择部队 → 地图逐站推进 → 节点详情卡片 |
| **长征图集** | 按事件编排的图集，可点开查看大图 |
| **长征精神** | 长征精神的五条权威概括，每条对应四路红军的真实经历，附来源注记 |

### 核心交互

- **路线动态绘制**：按节点顺序用平滑虚线 + 流动箭头逐站生长，支持播放 / 暂停 / 上一站 / 前进一站 / 直达终点 / 重走，速度三档可调。
- **节点交互**：地图标注全部关键历史节点，点击弹出详情卡（事件简介、详细史实、两段直线距离、史实来源入口）。
- **甘孜专题弹窗（重点）**：红二、六军团行进至**甘孜**节点时自动触发，说明红二方面军的组建过程，并明确指出**红四方面军并不并入红二方面军**——甘孜是「会合」不是「合并」。
- **史料注记**：内置「资料来源与注记」抽屉，展示底图来源声明、**底图领土完整性自检结果**、数据口径说明与全部史实来源。
- **地图漫游**：支持鼠标滚轮缩放与拖动；节点标记与名称标签由 HTML 覆盖层绘制并随漫游实时重算位置，不会错位。

### 数据规模

四支部队共 **90 个历史节点**：红一方面军 37、红25军 12、红二、六军团 17、红四方面军 24。线路内容依据权威党史定本体系逐条校订，重大事件基本全收录。

## 三、快速开始

### 方式一：用仓库自带的 `run.cmd`（推荐，无需配置 PATH）

项目根目录下的 `run.cmd` 是一个命令包装器，会自动指向本机已安装的 Node / pnpm，**不需要手动配置环境变量**。在**项目根目录**下执行：

```bat
run install      :: 安装依赖
run dev          :: 启动开发服务器 → http://127.0.0.1:5173
run build        :: 生产构建 → dist/
run preview      :: 预览构建产物 → http://127.0.0.1:4173
run verify       :: 端到端交付校验
run check:data   :: 只校验史实数据
```

它同时兼容 `cmd.exe` 与 PowerShell（在 PowerShell 中写成 `.\run dev`）。

### 方式二：直接用 pnpm / npm

```bash
pnpm install
pnpm dev          # 开发预览 → http://127.0.0.1:5173
pnpm build        # 生产构建 → dist/
pnpm preview      # 预览构建产物 → http://127.0.0.1:4173
```

### 开始使用

打开 <http://127.0.0.1:5173> 后：**点顶部导航「深度交互」→ 点地图上的起点标记（或左侧浮窗里的部队）→ 进入该部队的行军故事**。

> 进入部队后**默认暂停**在出发地，按「继续」才开始逐站推进。

## 四、可用命令

| 命令 | 作用 |
| --- | --- |
| `run dev` / `pnpm dev` | 启动 Vite 开发服务器（热更新） |
| `run build` / `pnpm build` | 生产构建到 `dist/` |
| `run preview` / `pnpm preview` | 本地预览构建产物 |
| `run check:data` | **史实数据自检**：字段完整性、坐标是否在中国范围内、节点 id 唯一性、来源引用有效性、站间直线距离是否异常，以及需求专项断言（甘孜弹窗必存在、四支部队出发地一致、红25军人数表述、红二方面军终点将台堡、红四方面军含会宁会师） |
| `run verify` | **端到端交付校验**：工程文件齐全性 + 数据自检 + 底图领土表示 + 依赖与构建产物 |
| `run fetch:basemap` | 获取底图（本仓库已内置底图，通常不需要执行） |
| `run probe:basemap` | 探测候选底图来源的合规性（`--dump` / `--url`） |
| `run fetch:artwork` | 尝试从 Wikimedia Commons 抓取历史照片（**国内网络环境不可用**，改用人工放置，见第六节） |

`verify` 中的底图自检调用的是**与浏览器完全相同的一套逻辑**（`src/map/loadBaseMap.js` 的 `analyzeIntegrity`），因此脚本结论与界面告警始终一致。

## 六、配置说明

### 1. 底图（已内置，一般无需改动）

仓库**已包含** `public/map/china.json`（DataV 中国省级矢量数据，35 个要素），并通过领土完整性自检：

```
要素 35 个 · 台湾省 ✓ · 海南省 ✓ · 南海诸岛插图 ✓ · 九段线 ✓（按 adcode 识别 100000_JD）
```

> ⚠ **正式参赛前请更换为带审图号的标准地图。** 当前底图为公开矢量数据，**不是**自然资源部标准地图服务网站发布的带审图号标准地图。本作品不臆造、不冒用审图号。作品内的领土表示告警条会在缺失南海诸岛或九段线时**明确提示而非静默展示**。

替换方式：把符合要求的中国省级矢量 GeoJSON 覆盖到 `public/map/china.json`，并在 `public/map/sources.json` 里更新来源声明。详细合规要求见 [`public/map/README.md`](public/map/README.md)。

若需要额外补充「南海诸岛 / 九段线」要素，可另放 `public/map/nanhai.json`（当前**不存在**，因为内置底图已包含这些要素）。

### 2. 配图（占位插画 → 真实照片）

当前所有配图都是**作品自绘的矢量插画**（`src/components/EventArtwork.vue`，12 个内联 SVG 场景），无版权与来源风险、离线可用。

要替换为真实照片，**不需要改代码**：

1. 按 `docs/配图清单.md` 的建议准备照片（列出了 13 个最值得配图的节点）；
2. 图片按 `manifest.json` 里的 `file` 字段命名，放进 `public/art/`；
3. 在 `public/art/manifest.json` 对应节点上填写 `title` / `author` / `license` / `source`；
4. 把该条目的 `reviewed` 改为 `true`。

界面会在 `reviewed: true` 时自动显示照片，否则**一律回退到手绘插画**——这是刻意设计的门槛，避免来源未核实的图片被当作史料照片展示。

### 3. 标识（国旗 / 党徽）

| 标识 | 位置 | 状态 |
| --- | --- | --- |
| **五星红旗** | 顶部导航品牌标识、首页引题行 | **已按标准规格精确绘制**：旗面 3:2，大星中心 (5,5) 外接圆半径 3，四小星中心 (10,2)、(12,4)、(12,7)、(10,9) 半径 1 且各有一角正对大星中心 |
| **党徽（镰刀和锤头）** | 「长征精神」页页首 | ⚠ **几何化简化示意，比例与官方标准图案并不完全一致** |

> **正式提交前请替换党徽。** 从权威渠道（中国政府网、共产党员网）获取官方标准矢量图，保存为 `public/symbols/party-emblem.svg`，并按 [`public/symbols/README.md`](public/symbols/README.md) 把 `PartyEmblem.vue` 的内联 SVG 换成 `<img>`。使用处的红底、尺寸、圆角均无需改动。

`scripts/preview-symbols.py` 可按组件里同一套几何参数把两个标识栅格化成 PNG，供替换后复核图形。

### 4. 史实数据

四支部队的数据集中在 `src/data/armies.js`，每条节点字段如下：

```js
{
  id:       'r1-zunyi',            // 全局唯一
  name:     '遵义会议',             // 地图标签与进度轨道上的短名
  place:    '贵州遵义',             // 事件发生地
  coord:    [106.93, 27.73],       // [经度, 纬度] 近似点位
  date:     '1935年1月15日—1月17日',
  kind:     'meeting',             // 见 NODE_KINDS
  hardship: 2,                     // 1—5，界面已不展示，保留字段以便恢复
  brief:    '一句话简介',
  detail:   '详细史实'
}
```

约定：**每支部队的 `nodes[0].kind` 必须为 `start`，末节点必须为 `end`**（`check:data` 会强制校验）。

> ⚠ **改了节点 id 一定要同步这几处**：`src/data/artwork.js` 的 `ART_BY_NODE`、`src/data/miniGames.js` 的 `MINI_GAME_BY_NODE`、`public/art/manifest.json` 的 `photos`。`check:data` 已加入**交叉引用校验**，引用不存在的节点会直接报错（此前曾有三处因此静默失效）。

## 七、数据口径

- **总里程**采用权威表述（中央红军二万五千里等）。
- 界面中的**分段 / 累计直线距离**是按节点经纬度用半正矢公式测算的球面直线距离，仅用于直观表达行程跨度，**不等于实际行军里程**；实际里程远大于此。该口径在节点卡片与页脚均有明示。
- **兵力数字**不同史料记载有差异，采用常见权威表述。
- **红四方面军长征起始时间**采用「1935 年 3 月强渡嘉陵江」之说。
- **难度星级与行军艰难程度**：底层数据保留（`armies.js` 的 `stars` / `hardship`），但按作者要求**界面已不展示**。

完整说明见 [`docs/史实来源与注记.md`](docs/史实来源与注记.md)。

## 九、与需求文档的偏差（如实记录）

以下三处**有意偏离**需求文档，理由与恢复方式见 [`docs/需求实现对照.md`](docs/需求实现对照.md)：

1. **音效未实现**——浏览器自动播放策略会拦截未经用户手势的音频；科普作品中突兀音效也干扰阅读。
2. **难度星级与行军艰难程度已从界面移除（按作者要求）**——理由是「每支部队的行军过程都是艰难的，不可量化」；连带删除了引导语中失去指代对象的后半句。底层数据保留，恢复成本很低。
3. **点击起点直接进入部队故事（按作者要求）**——需求原文要求「点击起点图标弹出选择卡片」，现改为直接选中进入；「选择卡片」的职责由左侧选部队浮窗承担。

## 十、常见问题

**Q：页面白屏，控制台有报错。**
A：先在浏览器按 `F12` 看 Console 的红色报错。若是模块解析失败，多半是 `node_modules` 未安装完整，重新执行 `run install`。

**Q：端口 5173 被占用。**
A：`vite.config.js` 里未固定端口，Vite 会自动顺延到 5174 等，请注意终端里实际打印的地址。也可以先关掉旧的 dev server 再启动。

**Q：地图显示「底图加载失败」。**
A：说明 `public/map/china.json` 缺失或格式不对。执行 `run verify` 会明确报出是哪一项没通过。

**Q：`run install` 报 `[ERR_PNPM_IGNORED_BUILDS]`。**
A：pnpm 11 已不再读取 `package.json` 的 `pnpm` 字段，构建脚本许可写在 `pnpm-workspace.yaml` 的 `allowBuilds` 里，仓库已配置好。若被清掉，补回该文件即可。

**Q：地图上的节点标记位置是否精确？**
A：精确。节点标记是 HTML 覆盖层，位置由 `convertToPixel` 从经纬度实时换算，拖动/缩放时每帧重算；**锚点是圆点本身**（不是「圆点+标签」整体），因此标签的显隐与长短都不会让圆点偏移。

**Q：想换掉党徽。**
A：见第六节第 3 条，改一个文件即可。
